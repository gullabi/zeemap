# Decisions

**Who this is for:** anyone who wonders "why is it done this way?" or "who decides this?".
**How to use it:** each decided item gives the decision, the reason, what it costs, and where the evidence is. A decision
is never deleted: when it changes, the old row is marked "replaced by #n" and a new row is added. Open items say what has
to be decided and what waits for it. Numbering: decided items are 1, 2, 3, ...; open questions are D2, D3, ...
When an open question is settled, it moves to the decided table with a new number, and its D number is noted there
(D1, the repository, became #9).

Decisions are taken by the maintainers. Until publication (2026-11) zeemap was built with one
maintainer, named "the maintainer" below. Most evidence comes from the research that preceded zeemap (2026-10-17) and
from a design review of 2026-10-19/20 ("review section n" below); neither is published, so the evidence column names
the kind of study. All research numbers are exploratory: they come from agent scripts, not from recorded runs. Where a
reason rests on an unpublished fit of a real star, it is stated in words, without numbers.

## Open questions

Each has a `[NEEDS DECISION Dn]` marker where it blocks (SPEC.md section 8).
- **D7.** Teff free by default? A free Teff can run to the edge of a library's temperature grid, so the grid must
  extend beyond the expected range. Waiting: the LIB-3 default.
- **D8.** Allow priors for the MCMC in the configuration (for example on the inclination)? Without them, the start
  distribution is the prior. Waiting: PAR-4.
- **D12.** Which view is the unit of uncertainty for published results: the fingerprint modes with per-mode MCMC, or
  the families with profiles and envelopes (decision #29)? Both are built, so nothing in the code waits. Waiting: the
  wording of error-bar statements, and whether SEARCH-7's band and REP-1's table are kept per mode or per family. To
  be settled from side-by-side comparisons on real objects (task T7.12).
